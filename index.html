Post-Mortems

$ grep -A4 "INCIDENT" ./var/log/postmortems.log
SEV-2 Idempotency gap under retry storm
IPCOM · CPaaS messaging fleet

symptom: duplicate SMS/voice events billed twice during a carrier retry storm — client-facing invoices didn't reconcile.

root cause: the ingestion handler treated every retry as a new event. No dedup key, no lock — just first-come-first-processed against Postgres, which meant two goroutines could both "win" the race.

fix: SetNX-based distributed lock keyed on carrier event ID, TTL-bounded to the retry window, backed by a gobreaker circuit breaker so a slow downstream doesn't cascade into a lock pileup.

lesson: "exactly-once" doesn't exist at the network boundary. Build for at-least-once delivery and make idempotency a first-class part of the schema, not an afterthought bolted on after the first incident.

SEV-3 Shared session token enabled account takeover surface
BYONDIT · digital wallets, 3 LATAM markets

symptom: security review flagged that a session token issued on one device remained valid on any device — no per-device binding, no forced logout on suspicious activity.

root cause: the legacy SOAP core banking layer was built for a single-device era and exposed session state directly to mobile clients without an intermediary gateway to enforce device-level policy.

fix: KrakenD custom plugins to bridge SOAP↔REST behind OAuth2/OIDC via AWS Cognito, with per-device PIN binding and automatic lockout after failed attempts — rolled out with zero downtime across all 3 markets.

lesson: legacy protocol boundaries are also trust boundaries. Modernizing the transport (SOAP → REST) is only half the job — the harder half is deciding what the gateway is allowed to assume about the client.

SEV-3 CI quota exhausted before the team's day started
Independent contract · platform tooling

symptom: a single full rebuild took ~6 hours and consumed the entire daily CI quota — one build per day, and if it failed, the team lost the rest of the day.

root cause: the pipeline rebuilt every package on every commit regardless of what actually changed. No dependency graph, no caching, no way to tell "affected" from "everything."

fix: dependency-graph analysis to isolate affected packages, combined with remote artifact caching and stage parallelization — went from 1 build/day to 20+ incremental builds on the same quota and cost.

lesson: throughput problems are often graph problems in disguise. Before adding more compute, ask what the build actually depends on — most CI time is spent rebuilding things nothing downstream needed.
