How I build systems

Three constraints that shape every architectural decision, from schema design to deployment strategy.

resilience.go
Resilience by design
retry loop without backoff no idempotency key circuit breaker + fallback Redis SetNX idempotency // exactly-once semantics

Systems that fail gracefully under load. Circuit breakers prevent cascade failures; Redis SetNX ensures payment operations never double-execute.

bridge.go
Incremental modernization
SOAP/XML monolith Oracle PL/SQL coupling Go REST adapter layer strangler fig migration // no big bang rewrites

Legacy systems aren't replaced in one sprint. I build adapter bridges that let old and new run in parallel until the risk window closes.

pipeline.yml
Pipeline efficiency
sequential build jobs no dependency graph graph-driven parallelism cache-aware CI layers // 1→20+ builds/day

CI/CD bottlenecks compound across every engineer on the team. Dependency graph analysis finds the real blocking jobs, not the obvious ones.

Shipped systems, measured outcomes

Three cases across CPaaS, fintech, and developer tooling — each with a friction, a decision, and a number.

High Concurrency
IPCOM
CPaaS Messaging Platform
Friction
Monolithic SMS/voice broker couldn't sustain peak load without message loss and SIP session contention.
Engineering applied
Distributed NATS message bus with PJSIP session management, async workers, and back-pressure queues decoupled ingestion from processing.
Output
1M+ msgs/day no message loss Go + NATS
Zero Downtime
BYONDIT
Fintech Wallet — LATAM
Friction
Banking core exposed only SOAP/XML. Three country deployments required simultaneous cutover with PCI compliance and zero tolerance for transaction errors.
Engineering applied
Go service as SOAP→REST translation layer with idempotency tokens per transaction. Strangler fig pattern enabled parallel-run validation before each market cutover.
Output
3 markets 0 downtime idempotent ops
Dev Velocity
Upwork Consulting
CI/CD Optimization
Friction
Sequential GitHub Actions pipeline limited the team to 1 successful build per day. Build times blocked every PR merge.
Engineering applied
Dependency graph analysis identified parallelizable stages. Restructured workflow YAML with cache-aware layering and matrix jobs eliminating sequential bottlenecks.
Output
1→20+ builds/day GitHub Actions graph analysis
